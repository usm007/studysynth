# CTET Mock PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a mobile-installable PWA named **CTET Mock** that runs fully offline on a phone, hosts generated CTET mock-test web apps, and classifies them on a landing page as Paper → Subject → Class → Lesson → Mock.

**Architecture:** A self-contained side project under `ctet-mock/` in the StudySynth repo. `build.py` (stdlib Python) scans `public/mocks/`, classifies each mock, rewrites the mock's embedded package title for uniqueness, and emits `public/catalog.json` + a content-hashed `public/sw.js`. The runtime is a static shell (`index.html` / `app.js` / `app.css`) plus a `player.html` that embeds a chosen mock in an iframe. The service worker precaches the shell, the catalog and every mock, so the whole library is offline after install. Deployed to Vercel as a plain static site.

**Tech Stack:** Plain HTML/CSS/JS (no framework, no bundler, no CDN, no webfont). Python 3.12 stdlib for the build step (including a hand-rolled PNG encoder for icons). `unittest` for tests, Playwright (Python) for browser/offline tests. Vercel static hosting.

**Spec:** This document is the spec. Decisions below are final unless the user changes them.

---

## Global Constraints

- **Offline-first:** after install, every screen and every mock must work with the network off. No runtime network requests beyond the app's own origin.
- **No new dependencies:** no npm, no CDN, no webfonts, no remote images, no analytics. System font stacks only.
- **Pristine mocks:** the generated mock HTML must remain a valid standalone app. Only the embedded package's `meta.title` may be rewritten (for session-key uniqueness), and that rewrite is opt-out via `--no-retitle`.
- **Determinism:** the same inputs must always produce the same `catalog.json` and the same service-worker version. No timestamps inside hashed content.
- **Warm Study Desk tokens** (match the existing mock UI family): bg `#f3f0e6`, surface `#fffefa`, surface-2 `#f6f4eb`, ink `#1f2620`, muted `#5f6860`, line `#d8dcd2`, accent `#315d49`, accent-2 `#244b3a`, accent-soft `#dce9df`, good `#205f35`, bad `#a63028`, radius 16/10.
- **Accessibility:** every control is reachable by keyboard, has a text or `aria-label` name, and never relies on colour alone. Touch targets ≥ 44px.
- **Repo isolation:** nothing in this project may modify `scripts/`, `templates/`, `profiles/`, `tests/` of the main StudySynth project.

## Review Focus

Five input classes the spec implies but that are easy to get wrong. Each gets a test in the owning task.

1. **A mock file with no classification signal at all** (e.g. `mock.html`) — must land in a visible "Unclassified" bucket and make the build exit non-zero, never silently vanish.
2. **Two mocks of the same lesson with the same internal title** (e.g. "Light — Mock 1" and "Light — Mock 2" both titled `Light`) — must not share a session key, or the second mock opens showing the first mock's progress.
3. **A mock whose content changed but whose filename did not** — the service-worker version must change so the phone gets the new paper, not a stale cached copy.
4. **A single mock file that fails to fetch during precache** (e.g. a truncated upload) — must not abort the whole install; every other mock must still land offline.
5. **A learner whose browser has no `beforeinstallprompt`** (iOS Safari, in-app browsers) — the install affordance must fall back to visible Add-to-Home-Screen instructions instead of a dead button.

## Task 2: Intake and classification engine

**Files:**
- Create: `ctet-mock/build.py` (classification half; Task 3 and 4 extend it)
- Test: `ctet-mock/tests/test_intake.py`

**Interfaces:**
- Produces: `parse_tokens(stem: str) -> dict` returning keys `paper`, `subject`, `klass`, `lesson_slug`, `mock_label` (any may be `None`).
- Produces: `read_package(html: str) -> dict | None` returning the embedded `meta` + `question_count` from the `/*__PACKAGE__*/{...}` literal.
- Produces: `classify(path: Path, html: str) -> dict` returning the final record: `{"file", "paper", "subject", "klass", "lesson", "mock_label", "title", "questions", "status", "source"}` where `source` is `"sidecar" | "filename" | "package" | "unclassified"`.
- Consumes: nothing from earlier tasks.

**Naming convention (the documented intake contract):**
`<paper>-<subject>-<class>-<lesson>-<mock>.html`, e.g. `p2-social-c8-natural-resources-m01.html`.

- paper tokens: `p1`, `p2`, `paper1`, `paper2`, `paper-i`, `paper-ii`
- subject tokens: `cdp`, `math`/`maths`/`mathematics`, `evs`, `science`/`sci`, `social`/`socialscience`/`socialstudies`/`sst`, `lang1`/`hindi`, `lang2`/`english`
- class tokens: `c6`/`class6`/`grade6`/`6` … through `c8`
- mock tokens: `m01`/`m1`/`mock1`/`set1`/`mock-01`
- remaining tokens join as the lesson slug (`natural-resources` → "Natural Resources")
- subject display names: "Child Development & Pedagogy", "Mathematics", "Environmental Studies", "Science", "Social Science", "Language I", "Language II"
- paper display names: "Paper I" (Class I–V), "Paper II" (Class VI–VIII)

**Resolution order:** sidecar `<stem>.meta.json` (explicit keys `paper`, `subject`, `class`, `lesson`, `title`, `mock`) → filename tokens → embedded package → unclassified.

**Package fallback rules:** class from `meta.source` / `meta.source_title` matching `Grade N` or `Class N`; lesson from `meta.title`; questions from `len(pkg["questions"])`; status from `meta.status`. If the class is known but the paper is not, infer Paper I for classes ≤ 5 and Paper II for classes ≥ 6.

## Task 4: Title uniqueness rewrite, service worker, and build CLI

**Files:**
- Modify: `ctet-mock/build.py`
- Test: `ctet-mock/tests/test_sw.py`

**Interfaces:**
- Produces: `rewrite_package_title(html: str, new_title: str) -> str` — replaces the embedded package's `meta.title` in place, leaving every other byte of the mock untouched. `build.py --no-retitle` skips it.
- Produces: `compute_version(files: list[Path]) -> str` — SHA-256 over `(relative path, file bytes)` pairs, truncated to 12 hex chars. Used as the catalog `version` and the cache key.
- Produces: `public/sw.js` with `const VERSION = "<12 hex>"`, `const CACHE_NAME = "ctet-mock-" + VERSION`, and `const PRECACHE = [...]` listing the shell, the catalog, the icons and every mock (paths relative to the service worker, no leading slash).
- Produces: `build.py` CLI: `python ctet-mock/build.py [--mocks-dir DIR] [--public-dir DIR] [--no-retitle] [--allow-unclassified]`. Prints a per-file classification table and a summary; exits non-zero when any file is unclassified unless `--allow-unclassified` is passed.

**Service worker contract:**
- `install`: open `CACHE_NAME`, then `Promise.allSettled` over every precache URL using `cache.add(new Request(url, { cache: "reload" }))` — one bad file must not abort the install. Then `self.skipWaiting()`.
- `activate`: delete every cache whose name is not `CACHE_NAME`, then `self.clients.claim()`.
- `fetch`: ignore non-GET and cross-origin. Cache-first for precached URLs; on miss, network with a cache write; on network failure, fall back to the cached copy, then to `index.html` for navigations.
- `message`: `{type: "SKIP_WAITING"}` → `self.skipWaiting()`.

- [ ] **Step 1: Write the failing test** — `test_sw.py` covers: the generated `sw.js` lists every mock URL; the version changes when a mock's bytes change and stays stable when nothing changes; `rewrite_package_title` changes only `meta.title` inside the embedded package; the generated SW contains `install`/`activate`/`fetch` handlers and no `http://` or `https://` URL; the SW source contains `Promise.allSettled` (partial-failure tolerance); `build.py` exits non-zero on an unclassifiable file and zero with `--allow-unclassified`.
- [ ] **Step 2: Run test to verify it fails** — `python -m pytest ctet-mock/tests/test_sw.py -v` → FAIL.
- [ ] **Step 3: Implement the remaining half of `ctet-mock/build.py`** — package-title rewriting, version hashing, SW template emission, and the CLI.

## Self-Review

**1. Spec coverage.** Every requirement from the user's brief maps to a task: mobile PWA → Task 1 (manifest) + Task 5 (mobile-first shell); works offline on a smartphone → Task 4 (SW) + Task 7 (offline test); hosts generated outputs → Task 2 (intake) + Task 3 (catalog); landing page classifies by paper/subject then class then lesson → Task 3 (tree) + Task 5 (drill-down); drop files in a folder and a script scans them → Task 2 + Task 4 CLI; Vercel hosting → Task 8; precache everything at install → Task 4.

**2. Step scan.** Every step names one file, one function signature, or one command. No step says "handle errors" or "add validation" without a named input.

**3. Type consistency.** `classify()` returns the record shape Task 3 consumes; `build_catalog()` returns the shape Task 5 and Task 6 consume; `compute_version()` feeds both `catalog["version"]` and the SW `VERSION` constant; `rewrite_package_title()` is used by the Task 4 CLI and asserted in Task 4's test.

**4. Review Focus.** (1) unclassified file → Task 2 and Task 4 tests. (2) duplicate titles → Task 3 uniqueness test and Task 4 rewrite test. (3) changed content → Task 4 version test. (4) partial precache failure → Task 4 `Promise.allSettled` assertion and Task 7 offline test. (5) no `beforeinstallprompt` → Task 5 static assertion that an install-instruction fallback exists.

**5. Proportion.** The plan is roughly the length of the implementation it describes; code bodies are left to the implementer except for the catalogue schema and the service-worker contract, which the spec pins exactly.
